# Architecture Plan — E3.5 Semantic duplicate / hidden-path detection (#58)

- **Mode:** plan (design-readiness gate for #58 — the epic success-metric differentiator).
- **Ticket:** #58 (E3.5). **Epic:** #3. **Depends-on:** #53 (ADR-0005), #54 (extraction), #57 (sameness building blocks).
- **Decision basis — no new ADR:** ADR-0005 already FIXED the algorithm (gated cascade), thresholds
  (0.94 / 0.02), the embedding model/port/adapter home, the post-hoc-pass design, and the budget/redaction
  discipline. #58 is the **implementation** of ADR-0005 §4.4 + §8 (#58 block) plus a small set of
  **sanctioned-additive contracts** in the same category ADR-0005 §10 already blessed. This is therefore a
  **per-ticket plan** (matching the `E3.1-workflow-extraction-plan.md` precedent), not a new ADR. Anything
  here that goes beyond additive (e.g. making `identify` async, splitting a bucket) would require a new ADR —
  nothing in this plan does.
- **Security controls owned:** M58.1–M58.3 (threat model E3) + the inherited HIGH controls T1/T2/T3/T4/T8.

## 1. Two load-bearing responsibilities (both in scope for #58)

Per the architect ruling on #57, #58 is **its own input-producer**:

1. **The post-hoc embedding-pass ORCHESTRATOR** (deferred from #57, ADR-0005 §4.4) — walks the finalized
   `StateGraph`, embeds once per distinct a11y bucket (budgeted/cached/redacted), runs the **already-built**
   `SamenessRefiner`, and produces the `CanonicalIdentityMap` + equivalence classes. `FakeEmbeddingPort` (imported
   by zero tests today) gets its first real consumer here, and the **one-embedding-per-bucket cache assertion**
   lands here.
2. **The semantic duplicate / hidden-path DETECTOR** — consumes those equivalence classes + #54 workflows
   (+ optional #55 intent), flags workflows that reach the **same canonical outcome via DISTINCT raw identities**,
   sets `Workflow.isHiddenPath = true` on the less-prominent route, and emits an expressible duplicate-group
   association for #59/E4. **Precision over recall** is the governing bias.

The detector is the **semantic complement** to E2's structural `DuplicatePathDetector` (same-raw-identity
convergence), not a rewrite of it. **#58 scopes itself to the CROSS-identity case E2 misses** (raw outcome ids
differ, canonical id same); pure same-raw-id convergence stays E2's (`duplicatePathNodeIds`).

## 3. Responsibility 1 — `RefineIdentities` (the orchestrator)

### 3.1 Interface (DI, ports-only — NFR1/T8)

```ts
export interface RefineIdentitiesResult {
  readonly canonicalMap: CanonicalIdentityMap; // = RefinementResult.canonicalBySignature (feeds R2 + #59)
  readonly classes: ReadonlyMap<StateIdentity, readonly StateIdentity[]>; // equivalence classes
  readonly deadBandNotes: readonly DeadBandNote[]; // telemetry only (never acted on)
  readonly embeddingCallCount: number; // for the budget/cache assertions
}

export class RefineIdentities {
  constructor(
    private readonly embeddings: EmbeddingPort, // real adapter in adapters/llm; FakeEmbeddingPort in tests
    private readonly cache: EmbeddingCachePort, // one-vector-per-bucket; E7-persistable
    private readonly redactor: CredentialRedactor, // TB-RED — redact BEFORE egress (T1)
    private readonly budget: EmbeddingBudgetGuard, // counts vs CrawlBudget (T3)
    private readonly refiner: SamenessRefiner, // #57 domain core — UNCHANGED
    private readonly projectSkeleton: (redactedSnapshot: string) => string, // injected; default = domain projectA11ySkeleton
    private readonly config: RefineIdentitiesConfig,
  ) {}

  async execute(graph: StateGraph, intent?: IntentModel): Promise<RefineIdentitiesResult>;
}
```

### 3.2 Flow (the post-hoc pass, ADR-0005 §4.4 / §5)

1. **Distinct buckets = `graph.nodes` keys.** E2 already keyed nodes by `A11ySignatureStrategy` identity, so each
   node _is_ a distinct a11y bucket — "one embedding per distinct bucket" == one embedding per node. Iterate nodes
   **sorted by `StateIdentity`** (determinism, independent of graph build order).
2. **Per bucket:** `cache.get(node.id)` first. On miss, **redact then project**:
   - `redact()` (structural secure-field masking) → `redactText()` (OTP/typed-secret masking) — the **same two-pass
     `CredentialRedactor` discipline `InferIntent` uses** (T1/NFR5). No inference path reads pre-redaction text.
   - `projectSkeleton(redactedSnapshot)` → the **normalized** skeleton (volatile content suppressed). Embedding the
     normalized skeleton — not the raw redacted snapshot — is **load-bearing for the recall-floor merge**: two
     buckets of the same screen normalize to near-identical skeletons → high cosine → merge.
   - If `budget.canCall()` → `await embeddings.embed({ skeletonText, cacheKey: node.id })`; `budget.recordUsage(promptTokens, 0)`
     **after every attempt** (failures count, T3); `cache.set(node.id, vector)`. An empty/low-dim vector or budget
     exhaustion ⇒ this bucket carries **no embedding** (a11y-only — never a guessed merge, NFR6).
3. **Labels (optional veto input):** if `config.labelsFromIntent` and an `intent` is supplied, set a bucket's
   `semanticLabel` **only when `ScreenIntent.source === "llm"`** (a confident label). Degraded/a11y purposes are NOT
   passed — an over-eager veto only ever _suppresses_ a merge (a miss, the safe direction), but we keep it conservative.
4. **Build `BucketInput[]`** `{ signature: node.id, embedding?, semanticLabel? }` and call `refiner.refine(buckets)`.
5. **Return** `RefinementResult` fields + `embeddingCallCount` (from the guard / fake).

`SamenessRefiner` and `CompositeStateIdentityStrategy` are consumed **unchanged** — #58 supplies their inputs and
reads their outputs. The synchronous `identify` contract is untouched (async work lives in this use-case).

### 3.3 Budget & cache (ADR-0005 §5; coordinator obligation #1)

- **`EmbeddingBudgetGuard`** is shape-identical to `IntentBudgetGuard` (`canCall`/`recordUsage`/`callsUsed`/`tokensUsed`
  over `CrawlBudget`). **Default per ADR-0005 §5: fold into the existing `maxLlmCalls`/`maxTokens` ceiling** — no
  `maxEmbeddingCalls` knob (YAGNI; add only if eval shows embedding volume needs independent bounding). _(Candidate
  for unification with `IntentBudgetGuard` into one shared `BudgetGuard` — deferred to #59 to avoid editing
  #55-owned code; called out in §8.)_
- **`EmbeddingCachePort`** (additive domain port) earns its place for: the one-per-bucket assertion being meaningful,
  re-run reuse (NFR3/T3), and the E7 persistence path (key = `StateIdentity`, never raw text). `InMemoryEmbeddingCache`
  mirrors `InMemoryDecisionCache`/`InMemoryIntentCache` exactly.

## 4. Responsibility 2 — `SemanticDuplicateDetector`

### 4.1 Interface (pure, sync, deterministic — no I/O, no SDK)

```ts
export interface DuplicateDetectionResult {
  readonly workflows: readonly Workflow[]; // COPIES with isHiddenPath set (immutability)
  readonly duplicateGroups: readonly DuplicatePathGroup[];
}

export class SemanticDuplicateDetector {
  constructor(private readonly config: DuplicateDetectorConfig) {} // { confirmWithIntent: boolean }
  detect(
    workflows: readonly Workflow[],
    canonicalMap: CanonicalIdentityMap,
    intent?: IntentModel,
  ): DuplicateDetectionResult;
}
```

```ts
// packages/domain/src/models/duplicate-path.ts  (additive — the expressible association for E4)
export interface DuplicatePathGroup {
  readonly outcomeIdentity: StateIdentity; // the shared CANONICAL outcome these paths converge on
  readonly workflowIds: readonly string[]; // all converging workflow ids (sorted, deterministic)
  readonly canonicalWorkflowId: string; // the PROMINENT route (not hidden)
  readonly hiddenWorkflowIds: readonly string[]; // routes flagged isHiddenPath = true
}
```

### 4.2 Algorithm

1. **Outcome identity** of a workflow = canonical id of its terminal step's `stateId`
   (`canonicalMap.get(rawOutcomeId) ?? rawOutcomeId`).
2. **Group** workflows by canonical outcome identity.
3. A group is a **semantic duplicate set** iff it has ≥2 workflows whose **RAW** terminal ids are **not all identical**
   (i.e. at least one _cross-identity_ merge — the case E2 misses). Pure same-raw-id convergence is E2's structural
   case and is **left to E2** (not flagged here) — keeps #58 the semantic complement and avoids double-flagging.
4. **Precision-confirmation gate (default ON, `confirmWithIntent`):** before emitting a group, if `intent` is
   supplied, require the outcome screens' `ScreenIntent.purpose` to **not confidently conflict** (both `source==="llm"`,
   normalized, disagree ⇒ **suppress** the group). This is a **class-level** label check at _flag time_ — it catches
   the **transitive label-veto bypass** the refiner's pairwise veto can miss (A–C–B co-classing). A disagreement
   suppresses the flag (precision wins). Absent/degraded/agreeing intents never suppress.
5. **Prominence (deterministic):** the prominent route = fewest steps (most direct); tie-break by
   lexicographically-smallest workflow id. Every other route in the set gets `isHiddenPath = true`.
6. **Emit** one `DuplicatePathGroup` per qualifying set; return new `Workflow` copies (never mutate inputs).

### 4.3 Why this is precision-biased by construction

- The detector **introduces no new merging** — it only _reads_ the refiner's classes. A false duplicate can only
  originate from a false MERGE upstream, which ADR-0005 already biases against (0.94 gate, dead-band→distinct,
  merge-only, label veto). The detector then adds a **second** precision gate (§4.2 step 4) at flag time.
- Restricting to **cross-identity** convergence + the **intent-confirmation** gate means a similar-but-distinct pair
  (refiner kept them distinct → different canonical ids) is **never** grouped — the precision floor (eval-2).

## 6. Acceptance criteria (Given/When/Then)

**Differentiator (the epic success metric)**

- **AC1 (genuine hidden path).** Given the fixture graph with two distinct-a11y outcome buckets the refiner merges
  (scripted cosine ≥ 0.94, agreeing labels), reached by two workflows of different lengths, When `RefineIdentities`
  then `SemanticDuplicateDetector` run, Then ≥1 `DuplicatePathGroup` is emitted, the longer route has
  `isHiddenPath = true`, the shorter is the `canonicalWorkflowId` — **deterministically, with no real LLM and no simulator**.
- **AC2 (precision floor — must NOT flag).** Given two similar-but-distinct outcomes (scripted cosine < 0.94, e.g.
  "Order confirmed" vs "Order cancelled"), When detection runs, Then **no** group is emitted and **no** workflow is
  flagged hidden.
- **AC3 (transitive-veto-bypass guard).** Given outcomes A and B that co-class transitively via middle bucket C, but
  whose outcome `ScreenIntent` (source `llm`) confidently conflict, When detection runs with `confirmWithIntent`, Then
  the false duplicate is **suppressed**; and given a clean transitive merge (no conflict) it **is** flagged.

**Budget / cache / redaction (the inherited HIGH controls)**

- **AC4 (one embedding per bucket).** Given a graph with N distinct buckets, When `RefineIdentities.execute` runs,
  Then `FakeEmbeddingPort.callCount === N` and `cacheKeys` equal the N distinct identities (no duplicate embed call).
- **AC5 (cache reuse).** Given the `EmbeddingCachePort` is pre-populated for a bucket, When `execute` runs, Then
  `embed` is **not** called for that bucket.
- **AC6 (budget bound).** Given a `CrawlBudget` permitting K < N calls, When `execute` runs, Then `callCount ≤ K`,
  the remaining buckets are a11y-only (no merges among them), and **exactly one** result is still produced (NFR6).
- **AC7 (redaction before egress, T1/T2).** Given a node whose a11y snapshot contains a seeded secret/PII, When
  `execute` runs, Then the `skeletonText` passed to `embed` contains no secret pattern, and no `DuplicatePathGroup`
  string carries secret/PII (groups carry only ids/flags anyway).
- **AC8 (boundary, T8).** No `@anthropic-ai/sdk` / `@ai-sdk` / `ai` import in `application`/`domain`; every embedding
  call routes through `EmbeddingPort`. dependency-cruiser + eslint-boundaries + cycles green.

**Degradation / determinism**

- **AC9 (degrade).** Given an empty / single-node graph, or a degraded (empty/low-dim) embedding, When the pass runs,
  Then it yields a valid empty/near-empty result and never crashes (NFR6).
- **AC10 (determinism).** Given the same graph + same fake embeddings/intent, repeated runs produce deep-equal
  `RefineIdentitiesResult` and `DuplicateDetectionResult` (including group + hidden-path assignment).
- **AC11 (≥3 eval scenarios bite in CI).** `docs/sdlc/evals/duplicate-paths/` encodes true-duplicate-flagged (AC1),
  false-duplicate-rejected (AC2), and hidden-path-marked/transitive-guard (AC3) as runnable tests; the
  `docs/sdlc/evals/sameness/README.md` one-per-bucket over-claim is corrected to point at the AC4 orchestrator test.

## 9. Risks

- **R-1 (false MERGE upstream → false duplicate).** The detector inherits the refiner's precision; a mis-tuned 0.94
  could over-merge. **Mitigated** by the §4.2-step-4 intent-confirmation gate (second precision check), cross-identity
  scoping, and the eval-2 precision floor that bites in CI. Worst case (under-merge) = E2 behaviour (the safe direction).
- **R-2 (transitive label-veto bypass).** Pairwise veto can be bypassed via an unlabeled middle node. **Measured** on
  the AC3 convergent-path fixture; **mitigated** at flag time by the class-level intent-confirmation gate rather than
  editing the #57 refiner. If eval shows a surviving false MERGE, a class-level conflict check at union time inside
  `SamenessRefiner` is the deferred ADR-level follow-up (not done speculatively — YAGNI).
- **R-3 (skeleton-projection coupling).** Reusing the E2 projection via the additive `projectA11ySkeleton` export keeps
  the embedding input DRY-consistent with the identity hash; the extract is behaviour-preserving and covered by existing
  #34 identity tests. Flagged additive to arch-review.
- **R-4 (cross-pass budget starvation).** Folding embeddings into `maxLlmCalls`/`maxTokens` could starve intent/naming
  LLM calls (or vice versa) once #59 unifies the counter. **Mitigated** by ADR-0005 §5's documented default + the
  optional `maxEmbeddingCalls` escape hatch if eval shows independent bounding is needed (not added now).
