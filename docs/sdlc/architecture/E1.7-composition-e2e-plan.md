## 1. Composition-root wiring

### 1.1 What already exists (no change needed)

`wire.ts` already binds **both** ports to a single `MobileMcpDriver` instance:

```
const mobileDriver = new MobileMcpDriver(defaultMcpConfig);
ports.mobileDriver = mobileDriver;
ports.simulatorLifecycle = mobileDriver;   // facade implements both ports
```

The facade (`MobileMcpDriver`, frozen by #12) delegates every port method to the capability bundle from
`defaultCapabilities(config.server)`, which already wires the **real** lifecycle / driving / snapshot / health
classes (each capability `index.ts` aliases its real class to the `*Stub` name the frozen `capabilities.ts`
imports). Verified on `origin/main`: `health/index.ts` exports the real `HealthReadiness`. So the concrete driver
is already correct and already swappable in one place.

**The single-line swap point** is the adapter import + the two `MobileMcpDriver` constructions in `wire.ts`.
Swapping to a different `MobileDriverPort`/`SimulatorLifecycle` implementation is changing the class named on those
lines — no business logic moves. This satisfies the AC ("swapping the concrete driver is a single-line change").

### 1.2 What #18 adds

1. **Real env-driven config** replacing the hardcoded `defaultMcpConfig` block (see §2). Wiring stays logic-free —
   a small `loadMobileMcpConfig()` reader in `packages/api/src/config/` (presentation/composition concern, not
   the domain). `wire.ts` calls it and injects the result; no parsing logic inline in the wiring body.
2. **No facade/barrel edits required for the happy path** — `new MobileMcpDriver(config)` is the contract ADR-0002
   §5 specified. The two reconciliation/teardown gaps in §2.3 and §3.4 below are handled at the root or escalated,
   **without** editing frozen capability internals.

## 2. Config reconciliation (the decision)

Three capability files default their dirs independently. The composition root must inject **one coherent
production config**. Decisions:

### 2.1 App-bundle base dir — single source of truth

**Decision: `FLOWSCOUT_APP_BUNDLE_DIR` (env) is the sole source of truth, read once at the root and injected.**

- #14 lifecycle: today defaults base dir to `FLOWSCOUT_APP_BUNDLE_DIR` → `os.tmpdir()` _internally_.
- #16 snapshot: today defaults base dir to the `.app`'s parent dir when none supplied.
- These two independent fallbacks are exactly the kind of divergence the root exists to eliminate. The root reads
  `FLOWSCOUT_APP_BUNDLE_DIR` once and is the authority. The lifecycle internal fallback to `os.tmpdir()` stays as a
  safety net but production always provides the env var (documented as **required for the real round-trip** in
  `.env.example`).
- The `.app` itself must live **inside** `FLOWSCOUT_APP_BUNDLE_DIR` (the lifecycle T2 confinement check requires
  this). The round-trip harness documents this requirement.

### 2.2 Production snapshot mode — clean-install vs erase-reinstall

**Decision: production runs `clean-install` (erase-only) as the reset semantics for E1.**
Rationale:

- The success metric is "reset to a **clean** snapshot." `clean-install` (`simctl shutdown` → `erase`) restores
  the device to a deterministic factory-clean baseline — which is exactly the disposable-state guarantee the
  threat model (T8) and the epic metric ask for. After reset the round-trip re-installs + re-launches the fixture
  for the next iteration, so the app is present again each cycle.
- `erase-reinstall` is an optimisation (skip the explicit reinstall step) that is **not reachable through the
  public `MobileMcpDriver(config)` path**: the frozen `defaultCapabilities()` constructs `SnapshotManager` with
  **no `appBundlePath`**, so it always resolves to `clean-install`. Reaching `erase-reinstall` would require either
  widening the public surface (a new config field threaded into a custom capability bundle) or editing frozen
  files. **Neither is justified for E1** — `clean-install` fully satisfies the metric.
- Net: `appBundlePath` is **not** injected into the snapshot capability at the root for E1. The round-trip owns
  re-install explicitly via the lifecycle port, which is clearer and keeps `wire.ts` logic-free.

### 2.3 How `appBundlePath` flows

- For **install/launch**: `appBundlePath` + `bundleId` are **round-trip inputs** (env: `FLOWSCOUT_FIXTURE_APP`,
  `FLOWSCOUT_FIXTURE_BUNDLE_ID`), passed to `installApp(udid, appBundlePath)` / `launchApp(udid, bundleId)` by the
  E2E script — they are _operation arguments_, not driver construction config. This is correct: the driver is
  app-agnostic; the script chooses the app.
- For **snapshot**: not injected (per §2.2 — clean-install needs none).

**Consequence:** the production driver config is purely the MCP server config (`server: {...}`) plus the env-read
base dir for lifecycle confinement. No frozen-internal change. This is the simplest design that satisfies the
metric (avoid over-engineering — we are not threading erase-reinstall plumbing nobody needs for E1).

### 2.4 The env surface `wire.ts` reads (extend `.env.example`)

- `FLOWSCOUT_MCP_SERVER_COMMAND` (default `npx mobile-mcp`), `FLOWSCOUT_MCP_CONNECT_TIMEOUT_MS` (10000),
  `FLOWSCOUT_MCP_CALL_TIMEOUT_MS` (30000) → `MobileMcpDriverConfig.server`.
- `FLOWSCOUT_APP_BUNDLE_DIR` (required for real round-trip) → lifecycle confinement base.
- `serverEnv` stays `defaultServerEnv()` (PATH-only; T5). **No full env or config object is ever logged** — the
  loader logs at most the command name + timeout values (T5/threat-model #18).

## 3. E2E strategy (OQ3 — no guaranteed fixture `.app`)

Two-layer strategy so the round-trip _logic_ is always verified and the _real-simulator_ run is gated.

### 3.1 Layer A — always-on orchestration test (normal CI, ubuntu)

**A fake-driver-backed test of the round-trip SCRIPT.** Reuse `FakeMobileDriver` (#13, in
`adapters/mobile-mcp/src/testing`). The round-trip is refactored into a pure orchestration function:

```
roundTrip(driver: MobileDriverPort & SimulatorLifecycle, opts): Promise<RoundTripReport>
```

The script (boot → readiness-poll → install → launch → snapshot → tap → screenshot + a11y → reset, repeated N×)
is driven against `FakeMobileDriver` with `N≥3`. This runs in the existing `ci.yml` on ubuntu, asserts the call
sequence + ordering + that `dispose`/teardown is invoked, and counts toward the coverage gate. **This is where the
round-trip logic is provably correct without a Mac.**

- Readiness gating: the script polls readiness between launch and first interaction. Because `checkReadiness` is
  **not** on `MobileDriverPort`/`SimulatorLifecycle` (it lives on the internal `HealthCapability`, unexposed —
  see §3.4), Layer A's readiness step is a **bounded retry of a real driver call** (e.g. `snapshotAccessibilityTree`
  until it succeeds or a config timeout elapses), which is portable across both layers and needs no surface change.

### 3.2 Layer B — gated macOS real-simulator E2E

A separate job (workflow_dispatch + label-gated, see §4) runs the SAME `roundTrip()` against the **real**
`MobileMcpDriver` on a `macos-latest` runner, only when a fixture `.app` is provided:

- **Fixture source (OQ3 decision):** `FLOWSCOUT_FIXTURE_APP` env/secret points to an **owner-supplied `.app`**
  inside `FLOWSCOUT_APP_BUNDLE_DIR`, with `FLOWSCOUT_FIXTURE_BUNDLE_ID`. If unset, the job **skips with a clear
  message** ("set FLOWSCOUT_FIXTURE_APP to run the real round-trip") and exits 0 — never a silent pass, never a
  red build for a missing optional fixture. Building the fixture is explicitly out of #18 (OQ3); a tiny buildable
  sample `.app` is a **recommended follow-up** (see §6) but not required to merge #18.
- **Fixture hygiene (T9):** the harness README documents that the fixture `.app` MUST be secret-free / PII-free
  (no embedded credentials, no real account data) and must never be committed to the repo.

### 3.3 Reliability + no-orphan assertion (T8) — applies to Layer B

- `roundTrip()` runs **≥3 consecutive iterations from clean state**; every iteration must succeed.
- **No-orphan assertion:** before the run, snapshot the set of booted sims + MCP child PIDs; after teardown,
  assert the set returned to baseline. Concretely: capture `xcrun simctl list devices booted` (UDID set) and the
  spawned MCP process before/after, and assert no new booted sim and no surviving MCP child remain after the
  final `dispose`. The harness wraps the run in `try/finally` so teardown runs even on assertion failure.
- **Teardown gap (see §3.4):** because the facade exposes no `dispose()`, Layer B's teardown calls
  `shutdownSimulator(udid)` (which it can, via the port) and additionally **kills the MCP child by PID** that the
  harness itself spawned/owns. The harness owns process lifecycle, not the facade.

### 3.4 Surfaced architectural gaps (decided, not deferred silently)

Two seams the round-trip needs are not on the public surface today:

1. **Readiness** is internal (`HealthCapability.checkReadiness`), not on `MobileDriverPort`/`SimulatorLifecycle`.
   **Decision for #18: do NOT widen the port.** Layer A/B gate readiness via bounded-retry of an existing port
   call (§3.1). Exposing readiness on the port is a deliberate E2 concern (the crawl engine needs it) — file as a
   follow-up when E2 needs it, not now.
2. **MCP teardown / `dispose()`** is not on the facade; `defaultCapabilities()` owns the `McpConnection`
   internally. **Decision for #18: the E2E harness owns the MCP child process lifecycle** (it spawns/observes the
   server process for the no-orphan assertion) rather than reaching through the facade. This keeps frozen files
   untouched. **A facade `dispose()` is the right long-term fix** (ADR-0002 §5 even says "cleanup on dispose") and
   is filed as a follow-up (see §6) — but it requires editing the frozen facade + barrel, which is out of #18's
   `packages/api`+CI+e2e lane and should not be smuggled in here.

## 4. CI placement + epic scanning policy

### 4.1 macOS E2E job — off the per-PR fast path

New workflow `.github/workflows/e2e-macos.yml`:

- `runs-on: macos-latest`; triggers: `workflow_dispatch` **and** `pull_request` gated by the label
  `e2e-macos` (so it never runs on the default per-PR path — ADR-0001 §7 plane 2). Not a required check for
  auto-merge.
- Steps: checkout → setup node 22 + pnpm → install → build → run `e2e/round-trip.e2e.ts` (Layer B). Skips with a
  clear message when `FLOWSCOUT_FIXTURE_APP` is unset (§3.2).
- **WDA loopback (T7):** if mobile-mcp/WDA binds a port, the job sets it to loopback-only and the harness asserts
  no non-loopback bind. Documented in the harness README.
- **Artifacts (T4):** round-trip screenshots/snapshots write to a **gitignored, non-world-readable** working dir
  (`.flowscout-e2e-artifacts/`, added to `.gitignore`, created `chmod 700`). Never committed. CI may upload as a
  build artifact but they never enter git.

### 4.2 Epic scanning policy — lands in the per-PR `ci.yml` (must be green before #18 merges)

Add to `ci.yml` (ubuntu, fast path):

- **Secret scan — gitleaks:** already present. Keep. Failure threshold: **any** finding fails.
- **SCA — dependency vulnerabilities:** add `pnpm audit --audit-level=high` (and/or `osv-scanner`). Threshold:
  **fail on high or critical**; moderate/low report-only (documented allowlist for unfixable transitive lows).
- **SAST — `eslint-plugin-security`:** add to the shared eslint config; runs inside the existing Lint step.
  Threshold: its rules are **errors** (fail the build), consistent with the repo's zero-lint-error policy.

Rationale for fast-path placement: gitleaks/SCA/SAST are cheap and platform-agnostic; they belong on every PR, not
behind the macOS gate. Only the slow real-simulator run is gated.

## 5. Test strategy + coverage

- **Layer A orchestration test** (`e2e/round-trip.orchestration.test.ts` or under `packages/api`): drives
  `roundTrip()` against `FakeMobileDriver`, asserts ordering, ≥3 iterations, teardown-invoked, skip/skip-message
  behaviour. Counts toward coverage.
- **`loadMobileMcpConfig()` unit tests**: env parsing, defaults, required-var handling, **no-secret-logging**
  assertion. Target **≥80% line+branch** on the config loader + the orchestration function (business/composition
  logic). `wire.ts` itself stays a thin composition root (low logic; the loader holds the testable parts).
- **Layer B** is the real-simulator plane (no coverage target; reliability-gated per §3.3).

## 6. Scope boundary — IN #18 vs. follow-up tickets

### IN #18

- Env-driven config loader + `wire.ts` injection (§1.2, §2).
- `e2e/` harness + `roundTrip()` + Layer A always-on test + Layer B gated macOS job (§3, §4.1).
- SCA + SAST wired into `ci.yml`; gitleaks kept (§4.2).
- `.env.example`, `.gitignore` (artifacts dir), eslint config + `package.json` script edits.

### NOT in #18 — file as separate follow-up tickets

1. **simctl child-kill-on-timeout** (`packages/adapters/mobile-mcp/src/simctl.ts`, #12's frozen file). Today
   `runSimctlWithTimeout` rejects on timeout but does **not** kill the spawned `execFile` child — a timed-out
   `simctl` can linger (orphan risk, T8). Fixing it edits #12's file, outside #18's `api`+CI+e2e lane.
   **Suggested ticket:** _"E1 hardening: kill simctl child process on timeout (no orphaned exec children)"_ —
   Touches: `packages/adapters/mobile-mcp/src/simctl.ts` + its tests.
2. **Screenshot base64 size-gate-before-decode** (`packages/adapters/mobile-mcp/src/driving/normalization.ts`,
   #15's frozen file). Today `normalizeScreenshot` decodes base64 into a Buffer **before** the size check, so an
   oversized payload is fully allocated before rejection (partial-OOM / DoS surface, T3). The gate should reject
   on the encoded length first. Edits #15's file, outside #18's lane.
   **Suggested ticket:** _"E1 hardening: size-gate screenshot base64 before decode (reject oversized pre-allocation)"_
   — Touches: `packages/adapters/mobile-mcp/src/driving/normalization.ts` + its tests.
3. **(Recommended, lower priority) facade `dispose()` for MCP teardown** (`MobileMcpDriver.ts` + `index.ts`
   barrel). ADR-0002 §5 references "cleanup on dispose" but the facade exposes none; #18 works around it in the
   harness (§3.4). Long-term the facade should own teardown so production callers (E2 crawl engine) get clean
   shutdown without owning the MCP PID.
   **Suggested ticket:** _"adapter-mobile-mcp: expose MobileMcpDriver.dispose() for MCP transport teardown"_.
4. **(Recommended, OQ3 follow-up) tiny buildable sample `.app` fixture** so Layer B can run without an
   owner-supplied build. **Suggested ticket:** _"E1 E2E: minimal buildable sample iOS .app fixture for round-trip"_.
5. **(Deferred to E2) expose readiness on the driver port** — only when the crawl engine needs it (§3.4).
