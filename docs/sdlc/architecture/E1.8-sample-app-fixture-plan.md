# E1.8 (#29) — Minimal buildable sample iOS `.app` fixture for Layer B round-trip (OQ3)

- **Status:** Accepted (implementation plan; realises E1.7 plan §6 item 4 — the OQ3 follow-up)
- **Date:** 2026-06-23
- **Mode:** plan
- **Realises / refines:** `E1.7-composition-e2e-plan.md` §3.2 (fixture source), §3.3 (no-orphan), §4
  (CI), §6 item 4. References ADR-0002 §5 (driver is app-agnostic; app is an operation argument).
- **Threat model:** `docs/sdlc/security/e1-mobile-mcp-foundation-threat-model.md` — T2 (path
  confinement), T9 (no secrets/PII in fixtures). This ticket adds no new threat surface; it satisfies
  T9 by building a synthetic app from committed source.
- **Not a new ADR:** the form (build-from-source, no binaries in git) was already decided in E1.7 §3.2
  and the threat model. This doc is the implementation plan for a **test fixture**, kept deliberately
  minimal (no product code, no over-engineering). It slots beside `E1.7-`/`E2.7-` per-epic plan docs.

---

## 1. Problem & decision summary

Today Layer B (`e2e/round-trip.e2e.ts`) **skips with exit 0** when `FLOWSCOUT_FIXTURE_APP` is unset —
correct, but it means the real macOS round-trip never actually runs in CI without an owner-supplied
build. #29 removes that gap by providing a **tiny SwiftUI app, built from source via `xcodebuild`** for
the iOS Simulator, that becomes the **default fixture when no owner fixture is supplied**.

Decisions (all confirmed against the repo + local toolchain Xcode 26.5 + `xcrun simctl`):

| # | Decision |
|---|----------|
| D1 | **Fixture form:** single-screen SwiftUI app **built from source** via `xcodebuild` for `generic/platform=iOS Simulator`. **No prebuilt `.app` committed** (E1.7 §3.2; T9 — no binaries in git). |
| D2 | **Determinism:** the one screen has exactly one tappable control with a **stable accessibility identifier** (`fixture.primaryButton`) so the round-trip's tap + a11y-snapshot steps have a deterministic target. |
| D3 | **Bundle id:** `com.flowscout.fixture.sampleapp` (matches `.env.example` placeholder convention; no real org). |
| D4 | **Confinement (T2):** the built `.app` is **copied into** `FLOWSCOUT_APP_BUNDLE_DIR` so it resolves inside the lifecycle confinement base (`SimulatorLifecycleManager.installApp` → `canonicalizeAppPath(.., baseDir)`). The build output dir is gitignored. |
| D5 | **Build form choice:** a **Swift Package Manager project is NOT viable** for an app bundle — SPM builds libraries/executables, not `.app` bundles for the simulator. We use a **minimal `.xcodeproj`** (smallest thing `xcodebuild` can turn into a simulator `.app`). The `.xcodeproj` + `Sources/` + `Info.plist` are committed; the derived `.app` is not. |
| D6 | **Backward compatibility:** the owner-supplied path still wins. The build script + CI only supply the sample when `FLOWSCOUT_FIXTURE_APP` is **unset**; the existing skip-when-unset code path in `round-trip.e2e.ts` is **unchanged**. |

This is the simplest design satisfying the metric — we are not adding XCUITest targets, multiple
screens, asset catalogs, or a Mobile-MCP-specific harness; one screen + one identified button is enough
for boot → install → launch → snapshot → tap → screenshot/a11y → reset to exercise every port method.

## 2. Fixture form & project structure (D1, D2, D5)

A single-screen SwiftUI app. Smallest viable layout under `e2e/fixtures/sample-app/`:

```
e2e/fixtures/sample-app/
  SampleApp.xcodeproj/              # committed — minimal project (one app target, one sim destination)
    project.pbxproj
  Sources/
    SampleApp.swift                 # @main App entry (WindowGroup → ContentView)
    ContentView.swift               # one screen: a Text label + one Button
  Info.plist                        # CFBundleIdentifier = com.flowscout.fixture.sampleapp
  README.md                         # source provenance + T9 hygiene statement (§5)
  .gitignore                        # ignore build/ DerivedData/ *.app (belt-and-suspenders)
```

`ContentView.swift` requirements (the only behavioural contract the round-trip depends on):

- A visible `Text("FlowScout Fixture")` so the a11y tree is non-empty (`a11yLength > 0`).
- Exactly one `Button` carrying **`.accessibilityIdentifier("fixture.primaryButton")`** and a stable
  label (e.g. `"Tap me"`). The button toggles an on-screen `@State` counter/text so a future
  by-identifier tap has an observable effect. (The current round-trip taps coordinate `(0,0)`; the
  stable identifier is provided now so E2 by-element tapping has a deterministic target without
  re-touching the fixture — extensibility point.)
- No network calls, no credentials, no real data (T9).

`Info.plist` minimum keys: `CFBundleIdentifier=com.flowscout.fixture.sampleapp`,
`CFBundleName=SampleApp`, `CFBundleExecutable=SampleApp`, `UILaunchScreen={}` (empty dict — avoids a
storyboard dependency). Deployment target ≥ iOS 17 (SwiftUI `.accessibilityIdentifier` on `Button` is
long-stable; pick the project's lowest CI-available simulator runtime).

> **Provenance (T9):** all source is **authored in-repo for this ticket** — no third-party app, no
> copied binary, no SDK sample. Recorded in `e2e/fixtures/sample-app/README.md`.

## 3. Where it lives & how the `.app` lands in the confinement dir (D3, D4)

- **Committed:** everything under `e2e/fixtures/sample-app/` **except** build output.
- **Build output (NOT committed):** `xcodebuild` writes to a fixture-local derived-data dir; the script
  then **copies the resulting `SampleApp.app` into `FLOWSCOUT_APP_BUNDLE_DIR`** so install passes T2
  confinement (`installApp` canonicalises the path and rejects anything outside `baseDir`).
- **Bundle id** for `FLOWSCOUT_FIXTURE_BUNDLE_ID`: `com.flowscout.fixture.sampleapp` (must equal the
  `Info.plist` `CFBundleIdentifier` — the script reads it back from the built bundle rather than
  hardcoding a second copy, so the two can never drift; magic-constant-free).

**`.gitignore` additions (root):**

```
# --- E2E sample-app fixture build output (built from source; never committed) ---
e2e/fixtures/sample-app/build/
e2e/fixtures/sample-app/DerivedData/
e2e/fixtures/**/*.app
```

(The per-fixture `.gitignore` in §2 is a local guard; the root entries are authoritative.)

## 4. Build script (D4, D6)

New script `e2e/fixtures/sample-app/build-fixture.sh` — bash, `set -euo pipefail`, forward slashes,
no magic constants (all paths/ids are named variables sourced from one place), explicit error handling.

**Contract:**

- **Inputs (env, all optional with sane defaults):**
  - `FLOWSCOUT_APP_BUNDLE_DIR` — confinement base the `.app` is copied into. Default
    `"${TMPDIR:-/tmp}/flowscout-apps"` when unset (created `mkdir -p`). Echoed, never assumed.
  - `FIXTURE_SCHEME` (default `SampleApp`), `FIXTURE_SIM_DESTINATION`
    (default `generic/platform=iOS Simulator`).
- **Steps:**
  1. Resolve `PROJECT_DIR` from the script's own location (`dirname "$0"` → absolute via `cd`/`pwd`),
     so it runs from any CWD.
  2. Pre-flight: assert `xcrun` and `xcodebuild` exist; if not, **print a clear message and exit 0**
     (non-macOS / no-Xcode → skip, never red) — mirrors the round-trip's skip philosophy.
  3. `xcodebuild build -project SampleApp.xcodeproj -scheme "$FIXTURE_SCHEME"
     -destination "$FIXTURE_SIM_DESTINATION" -derivedDataPath "$PROJECT_DIR/DerivedData"
     CODE_SIGNING_ALLOWED=NO` (simulator builds need no signing).
  4. Locate the built bundle: `BUILT_APP="$PROJECT_DIR/DerivedData/Build/Products/Debug-iphonesimulator/SampleApp.app"`;
     assert it exists.
  5. `mkdir -p "$FLOWSCOUT_APP_BUNDLE_DIR"` and `cp -R` the bundle into it →
     `FIXTURE_APP="$FLOWSCOUT_APP_BUNDLE_DIR/SampleApp.app"`.
  6. Read the bundle id back from the copied bundle:
     `BUNDLE_ID=$(/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' "$FIXTURE_APP/Info.plist")`.
  7. **Emit exports for the round-trip.** The script writes the two values to `$GITHUB_OUTPUT`
     (and `$GITHUB_ENV`) **when running in CI**, and **always** prints
     `export FLOWSCOUT_FIXTURE_APP=... / export FLOWSCOUT_FIXTURE_BUNDLE_ID=...` to stdout so a local
     dev can `eval "$(e2e/fixtures/sample-app/build-fixture.sh)"`. It does **not** mutate the caller's
     shell directly (no source-required side effects).
- **Hygiene:** the script logs only the bundle path + id + destination — never env objects or secrets
  (consistent with the round-trip's T5 logging discipline).
- **Wiring helper script (root):** add `e2e/fixtures/sample-app/build-fixture.sh` and a root
  `package.json` script `"e2e:build-fixture": "bash e2e/fixtures/sample-app/build-fixture.sh"` so both
  CI and local devs invoke it the same way (no magic command duplicated across call sites).

## 5. CI wiring (D6)

Edit `.github/workflows/e2e-macos.yml` — add **one build step before** the round-trip step, made a
no-op when an owner fixture is already supplied (preserve existing behaviour):

1. New step `Build sample fixture (.app)` runs **only when `FLOWSCOUT_FIXTURE_APP` is empty** (i.e. no
   owner fixture from `inputs.fixture_app`/`secrets.FLOWSCOUT_FIXTURE_APP`). Guard with an `if:` on the
   resolved fixture value (or a small bash `[ -z "$FIXTURE" ]` early-exit inside the step).
2. The step sets `FLOWSCOUT_APP_BUNDLE_DIR` to a runner-local dir when the secret is unset
   (e.g. `"$RUNNER_TEMP/flowscout-apps"`), runs `pnpm run e2e:build-fixture`, and exports
   `FLOWSCOUT_FIXTURE_APP` + `FLOWSCOUT_FIXTURE_BUNDLE_ID` + `FLOWSCOUT_APP_BUNDLE_DIR` to `$GITHUB_ENV`.
3. The existing `Round-trip E2E (Layer B)` step is unchanged except its `env:` block now lets the
   `$GITHUB_ENV` values flow through: owner-supplied values take precedence (still injected from
   `inputs`/`secrets`); when those are empty, the built sample's exported values are present in the
   environment, so the round-trip runs instead of skipping.

**Net behaviour matrix (skip path preserved):**

| Owner `FLOWSCOUT_FIXTURE_APP` | Build step | Round-trip |
|---|---|---|
| set (input or secret) | skipped (owner wins) | runs against owner `.app` (unchanged) |
| unset, macOS + Xcode present | builds sample, exports vars | runs against built sample (**new default**) |
| unset, Xcode missing | build script prints skip, exits 0 | round-trip's own skip path → exit 0 (unchanged) |

No change to the per-PR fast path (`ci.yml` stays untouched — this is all behind the label-gated macOS
plane, ADR-0001 §7 plane 2).

## 6. Hygiene (T9) & test strategy

- **T9 assertion:** `e2e/fixtures/sample-app/README.md` states the app is authored in-repo, synthetic,
  contains no secrets/PII/credentials, and that the built `.app` is never committed. The committed
  source is plain Swift + plist — gitleaks (already in `ci.yml`) scans it on every PR; **any** finding
  fails. No new scanner needed.
- **No coverage target:** this is a build fixture, not business/domain logic — it adds **no TS units**
  and is **out of the ≥80% line+branch gate** (consistent with E1.7 §5, which excludes Layer B from
  coverage). The existing Layer A orchestration test continues to cover the round-trip logic on ubuntu.
- **Verification of this ticket** is the **Layer B job itself** going green on a `workflow_dispatch` /
  `e2e-macos`-labelled run with no owner fixture: ≥3 iterations, all succeed, no-orphan assertion
  passes. That is the acceptance signal.

## 7. Acceptance criteria (Given/When/Then)

- **AC1 — builds from source, no binary in git.**
  *Given* a clean checkout on macOS with Xcode, *when* `pnpm run e2e:build-fixture` runs, *then* a
  `SampleApp.app` is produced under `FLOWSCOUT_APP_BUNDLE_DIR` and **no `.app` / DerivedData / build
  output is tracked by git** (`git status` clean; `.gitignore` covers them).
- **AC2 — deterministic tappable target.**
  *Given* the built app, *when* it launches in the simulator, *then* its a11y tree is non-empty and
  contains exactly one control with identifier `fixture.primaryButton` (verifiable via
  `snapshotAccessibilityTree`).
- **AC3 — confinement (T2).**
  *Given* the script copies the `.app` into `FLOWSCOUT_APP_BUNDLE_DIR`, *when* the round-trip calls
  `installApp`, *then* it passes confinement (path resolves inside `baseDir`) and installs without an
  `InstallFailedError`/confinement rejection.
- **AC4 — bundle id consistency, no magic constant.**
  *Given* `FLOWSCOUT_FIXTURE_BUNDLE_ID` exported by the script, *when* compared to the built bundle's
  `Info.plist CFBundleIdentifier`, *then* they are equal (the script derives the id from the bundle, it
  is not hand-typed in two places).
- **AC5 — self-contained Layer B run.**
  *Given* no owner `FLOWSCOUT_FIXTURE_APP`, *when* `e2e-macos.yml` runs on macOS, *then* it builds the
  sample and the round-trip executes ≥3 iterations with `allSucceeded=true`, `teardownCalled=true`, and
  the no-orphan assertion passing — instead of skipping.
- **AC6 — owner-supplied path still works (no regression).**
  *Given* `FLOWSCOUT_FIXTURE_APP` is set (input or secret), *when* the workflow runs, *then* the build
  step is skipped and the round-trip uses the owner `.app` exactly as before.
- **AC7 — graceful skip without Xcode.**
  *Given* a non-macOS / no-Xcode environment, *when* the build script runs, *then* it prints a clear
  message and exits 0 (no red build), and the round-trip's existing skip path is untouched.
- **AC8 — T9 hygiene documented.**
  *Given* the fixture dir, *then* `README.md` documents provenance + secret/PII-free status, and
  gitleaks on the per-PR path reports no finding on the committed source.
